## Medium

### M1. `DELETE /calendar/:id` returns no `data`, docs say `{ success: true }`

- Docs: `documents/modules/calendar/calendar.controller.md:43` ("`data`: `{ success: true }`");
  `documents/api.md:9` lists logout as the only JSON route without `data`.
- Code: `server/src/calendar/calendar.controller.ts:133-138` awaits `deleteEvent` and returns `{ statusCode, message }`
  only. (`CalendarService.deleteEvent` returns `{ success: true }`, `calendar.service.ts:164`, but the controller drops it.)
- Differs: a client reading `data.success` gets `undefined`.
- Fix: in `calendar.controller.md:43` write "Response has no `data`." and in `api.md:9` change "logout has no `data`" to
  "logout and `DELETE /calendar/:id` have no `data`". (`calendar.service.md:40-41` is correct for the service.)

### M2. `summary.md` says every write tool waits for confirmation; two write tools run at once

- Docs: `documents/summary.md:42-43` "Write tools are not run until the user confirms."
- Code: `server/src/calendar/calendar.tools.ts:17-63` (`create_calendar_event`, no `requiresConfirmation`) and
  `server/src/ai-agent/tools/memory.tools.ts:42-75` (`save_user_memory`, no `requiresConfirmation`) run inside the
  chat loop (`server/src/ai-agent/services/agent/agent.service.ts:412-427`). Only `create_financial_transaction`,
  `update_calendar_event`, `delete_calendar_event`, `send_proactive_notification` are parked.
- Differs: the summary states a safety property the code does not have. `modules/ai/ai.service.md:32-43` and
  `modules/calendar/calendar.service.md:47-52` already show the correct flags, so the docs also contradict each other.
- Fix: `summary.md:43` → "Transaction creation, calendar update/delete and notifications are not run until the user
  confirms; creating a calendar event and saving a memory run at once."

### M3. Swagger is called the reference for response shapes; it has none

- Docs: `documents/api.md:3-4` ("Swagger at `/api/docs` is the reference for request and response shapes"),
  `documents/README.md:10` ("Swagger ... has the shapes"), `server/README.md:8` ("Swagger at `/api/docs` is the
  reference").
- Code: every handler returns an untyped object literal and declares `@ApiResponse({ status, description })` only, e.g.
  `server/src/finance/finance.controller.ts:44-55`, `server/src/ai-agent/ai-agent.controller.ts:49-60`. The Swagger CLI
  plugin (`server/nest-cli.json:7-14`) documents request DTOs but cannot infer a response schema from a literal.
- Differs: Swagger shows request bodies and status codes, not `data` shapes. The real response shapes are only in the
  module controller docs (`Response data` bullets).
- Fix: in all three places say "Swagger has the request shapes and status codes; response `data` shapes are in
  `modules/*/*.controller.md`."
